# Коннекторы (Connect-It)

Коннекторы позволяют Bot использовать инструменты сторонних сервисов, таких как GitHub и Notion. За ними стоит [Connect-It](https://github.com/memohai/connect-it) — сопутствующий сервис, развёртываемый рядом с Memoh. Все учётные данные (токены OAuth, ключи API) живут на стороне Connect-It; Memoh хранит только таблицу привязок: какой Bot привязан к какому подключению, как называется пространство имён инструментов и включено ли оно.

С точки зрения пользователя коннекторы не устанавливаются сами по себе: они приходят как компоненты [приложения](../guides/supermarket.md). Манифест приложения объявляет, какие типы коннекторов оно использует и какие из них обязательны; после установки вы авторизуете их на вкладке **Apps** нужного Bot. Остальная часть этой страницы — взгляд оператора: как запустить Connect-It и как подключения устроены изнутри.

---

## Требования к серверу

Функция коннекторов появляется, только когда на сервере настроен эндпоинт Connect-It:

```toml
[connect_it]
base_url = ""   # например, "http://connect-it:8421"
api_token = ""  # доверенный межсерверный токен
```

Если оставить оба значения пустыми, функция отключена. В продакшене предпочтительнее соответствующие переменные окружения (`MEMOH_CONNECT_IT_BASE_URL`, `MEMOH_CONNECT_IT_API_TOKEN`).

Server Deploy в одну команду при чистой установке поднимает совместно размещённый Connect-It; см. [Server Deploy](./docker.md#коннекторы-connect-it). Без настроенного Connect-It компоненты приложений, зависящие от коннектора, отображаются как недоступные.

## Авторизация и управление

После установки приложения с коннекторами вкладка **Apps** у Bot показывает их среди компонентов приложения с пометками **Needs authorization**, **Optional** или **Shared across workspaces**. Нажмите **Authorize**, чтобы завершить привязку: OAuth проходит через всплывающее окно (если браузер его блокирует, разрешите всплывающие окна для страницы), а коннекторы с ключом API вместо этого запрашивают поля учётных данных.

У каждого подключения отображается статус:

| Статус | Значение |
|--------|---------|
| **Connected** | Всё в порядке; инструменты доступны Bot |
| **Waiting for authorization** | Подключение создано, но OAuth так и не завершился; завершите его или отключите подключение |
| **Authorization required** | Учётные данные истекли или были отозваны; нажмите **Reauthorize** |
| **Authorization failed** | Последняя попытка авторизации не удалась; **Reauthorize** повторяет её |
| **Unavailable** | Настроенный Connect-It не предоставляет этот тип коннектора |
| **Disabled** | Выключено; инструменты Bot не передаются |

Подключение можно **включать и выключать**, не удаляя его. **Disconnect** убирает привязку у Bot **и** удаляет сохранённое подключение (вместе с учётными данными) на стороне Connect-It — приложения, которые им пользовались, придётся авторизовать заново.

## Как инструменты попадают к Bot

Во время беседы Memoh объединяет все включённые и исправные подключения Bot в одну MCP-сессию и передаёт её агенту как источник инструментов. Инструменты коннекторов появляются рядом с инструментами рабочего пространства и MCP.

Каждое подключение в момент привязки получает **пространство имён инструментов**, сгенерированное из типа коннектора: подключение GitHub — `github`, второе такое же — `github-2`. Пространство имён остаётся неизменным на весь срок жизни привязки: добавление или удаление других подключений позже никогда не меняет имена инструментов уже существующих.

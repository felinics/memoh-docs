# Провайдеры и модели

Чтобы полноценно пользоваться Memoh, обычно нужно настроить:

- один или несколько **провайдеров**, определяющих, как Memoh обращается к вышестоящим API;
- одну или несколько **моделей** под этими провайдерами;
- опционально **провайдеров речи**, если нужен синтез речи из текста;
- опционально **провайдеров транскрипции**, если нужно распознавание речи.

Провайдеры и модели для чата и эмбеддингов управляются на странице **Models** приложения. Модели речи управляются на странице настроек **Speech**, а модели транскрипции — на странице настроек Transcription.

---

## Основы провайдеров

**Провайдер** хранит сведения о подключении к одному вышестоящему сервису, например:

- протокол API (`client_type`);
- base URL, если протокол его требует;
- учётные данные — API-ключ или OAuth-токен.

Типичные примеры: OpenAI-совместимые конечные точки, Anthropic, Google Gemini, OpenAI Codex и GitHub Copilot.

### Создание провайдера

Провайдеры создаются из **каталога шаблонов**. Каждый шаблон уже несёт правильный тип клиента, base URL и подобранный список моделей, так что обычно остаётся только ввести API-ключ.

1. Откройте страницу **Models** в боковой панели настроек.
2. Нажмите **Add Provider** и выберите шаблон — список показывает только ещё не настроенные вами шаблоны и поддерживает поиск (в том числе по локализованным названиям вендоров).
3. Заполните учётные данные, которые запрашивает шаблон.
4. Сохраните. Провайдер и его предустановленные модели создаются при сохранении.

В комплект входят шаблоны OpenAI, Anthropic, Google, OpenRouter, DeepSeek, **Zhipu AI (bigmodel.cn)**, Z.AI, Azure OpenAI, Cerebras, Cloudflare, Fireworks, Perplexity, Together и другие. Обратите внимание: **Zhipu AI** (`open.bigmodel.cn`, аккаунты материкового Китая) и **Z.AI** (`api.z.ai`, международные аккаунты) — это разные шаблоны с раздельными пространствами API-ключей; выбирайте тот, где был выдан ваш ключ.

Если ни один шаблон не подходит, по-прежнему можно создать полностью пользовательский провайдер.

Основные поля:

| Поле | Описание |
|-------|-------------|
| **Name** | Удобное отображаемое имя, например `OpenAI` или `Copilot`. |
| **Client Type** | Протокол API, который использует этот провайдер. |
| **Base URL** | Корневая конечная точка API, когда её требует выбранный тип клиента. |
| **API Key** | Аутентификация по токену, когда тип клиента использует прямые учётные данные. |

Сейчас Memoh поддерживает следующие типы клиентов:

| `openrouter-speech` | Провайдеры речи OpenRouter |
| `openrouter-transcription` | Провайдеры транскрипции OpenRouter |
| `elevenlabs-speech` | Провайдеры речи ElevenLabs |

## Провайдеры на OAuth

Большинство типов провайдеров использует обычный API-ключ. Два заметных исключения — `openai-codex` и `github-copilot`. Оба аутентифицируются через **авторизацию устройства** по одному и тому же потоку, и ни у одного нет поля API-ключа:

1. Сначала создайте и **сохраните** провайдер — авторизация доступна только из панели деталей уже сохранённого провайдера.
2. В разделе **Account** нажмите **Connect**. Memoh покажет URL для проверки и одноразовый код пользователя с обратным отсчётом срока действия.
3. Нажмите **Copy & Open**, введите код на странице проверки провайдера — и Memoh завершит авторизацию автоматически.

> Вводите код только на показанном URL для проверки — коды устройства могут использоваться для фишинга.

После этого на провайдере отображается подключённый аккаунт, а **Revoke** отключает его.

### OpenAI Codex

- Использует тип клиента `openai-codex`; шаблон из комплекта указывает на `https://chatgpt.com/backend-api`
- Входит через ваш аккаунт ChatGPT

Хороший выбор, когда нужен доступ к моделям в стиле Codex для задач, ориентированных на код.

### GitHub Copilot

- Использует тип клиента `github-copilot`
- Входит через ваш аккаунт GitHub

GitHub Copilot особенно полезен, если у вас уже есть доступ к чат- и эмбеддинг-моделям на базе Copilot и вы хотите переиспользовать его из Memoh.

::: warning Примечание при обновлении
Раньше учётные данные Copilot хранились для каждого пользователя отдельно. Теперь это единые учётные данные уровня провайдера, как у Codex. После обновления существующего развёртывания один раз переавторизуйте провайдер Copilot.
:::

### Управляемые каталоги моделей

У обоих OAuth-провайдеров список моделей — это **управляемый каталог**, получаемый вживую от вышестоящего сервиса (у Codex статического списка моделей нет вовсе — он всегда отражает то, что доступно вашему аккаунту ChatGPT):

- Каталог синхронизируется автоматически после авторизации устройства, и его можно переимпортировать в любой момент.
- Модели, исчезнувшие из вышестоящего каталога, помечаются недоступными, а не удаляются.
- Переимпорт работает как upsert: новообнаруженные возможности дополняются, не перезаписывая вашу собственную конфигурацию моделей.

## Импорт моделей

Создав провайдер, вы можете импортировать или добавлять модели под ним.

Типичный порядок:

1. Выберите провайдер.
2. Нажмите **Import Models**, если провайдер умеет отдавать каталог моделей.
3. Отметьте модели, которые нужно сохранить в Memoh.

Можно добавлять модели и вручную, если вы уже знаете ID модели у вышестоящего сервиса.

### Включение моделей

У каждой строки модели на странице провайдера есть **переключатель включения**. Выключенные модели остаются там видимыми, чтобы их можно было включить снова, но исчезают из всех списков выбора моделей (настройки Bot, чат, эмбеддинги и так далее).

Значения по умолчанию зависят от того, как модель появилась:

- Модели, добавленные **вручную**, сразу включены.
- Модели, созданные **массовым импортом**, по умолчанию **выключены** — так импорт большого каталога не заполоняет все списки выбора; включайте только те, что действительно хотите использовать.

## Типы моделей

Memoh различает четыре типа моделей:

| Тип | Назначение |
|------|---------|
| `chat` | Основные LLM для разговора, вызова инструментов, рассуждений и генерации изображений |
| `embedding` | Векторные модели для памяти и поиска |
| `speech` | Модели синтеза речи, используемые TTS-провайдерами |
| `transcription` | Модели распознавания речи, используемые провайдерами транскрипции |

Важное разграничение:

- Страница **Models** — это в первую очередь место управления моделями `chat` и `embedding`.
- Модели `speech` доступны через страницу настроек **Speech**.
- Модели `transcription` доступны через страницу настроек Transcription.

## Настройка чат-модели

При добавлении чат-модели важнее всего такие поля:

| Поле | Описание |
|-------|-------------|
| **Model ID** | Точный идентификатор у вышестоящего сервиса, например `gpt-4o` или `claude-sonnet-4.6`. |
| **Name** | Удобное отображаемое имя в интерфейсе. |
| **Description** | Необязательный текст; показывается подсказкой в списках моделей, по нему работает поиск в списках выбора. |
| **Compatibilities** | Флаги возможностей, такие как `vision`, `tool-call`, `image-output` и `reasoning`. |
| **Context Window** | Примерный максимальный бюджет контекста модели. |

### Совместимости

По флагам совместимости Memoh решает, какие функции модель может безопасно обслуживать:

| Совместимость | Значение |
|---------------|---------|
| `vision` | Модель принимает изображения на вход |
| `tool-call` | Модель умеет вызывать инструменты |
| `image-output` | Модель умеет генерировать изображения |
| `reasoning` | Модель предоставляет явные режимы рассуждения / уровни усилий |

Если модель поддерживает рассуждения, она может также объявлять `reasoning_efforts`: `none`, `low`, `medium`, `high` или `xhigh`.

### `context_window`

`context_window` важен, потому что Memoh использует его, чтобы:

- вычислять использование контекста сессии в приложении;
- формировать вывод `/status`;
- определять, когда сессия приближается к лимиту промпта;
- направлять [сжатие контекста](../../guides/compaction.md).

Если оставить `context_window` пустым, моделью всё равно можно пользоваться, но Memoh не сможет показать точный процент использования для неё.

### Модели генерации изображений

Теперь Memoh позволяет назначить Bot отдельную модель **Image Generation Model**. Это должна быть чат-модель, среди совместимостей которой есть `image-output`.

Так генерацию изображений при необходимости можно держать отдельно от чат-модели по умолчанию.

## Модели эмбеддингов

Модели эмбеддингов используются для семантической индексации и поиска.

Обязательное поле:

| Поле | Описание |
|-------|-------------|
| **Dimensions** | Размерность вектора на выходе эмбеддинга, например `1536`. |

Используйте модели эмбеддингов с провайдерами памяти и любыми функциями, которые опираются на векторный поиск.

---

## Модели речи и транскрипции

Модели речи управляются на странице настроек **Speech**, а не через стандартный поток чат-провайдеров.

Текущие категории провайдеров речи:

- Edge через `edge-speech`
- OpenAI-совместимые через `openai-speech`
- OpenRouter через `openrouter-speech`
- ElevenLabs через `elevenlabs-speech`
- Deepgram через `deepgram-speech`
- MiniMax через `minimax-speech`
- Volcengine через `volcengine-speech`
- Alibaba Cloud через `alibabacloud-speech`
- Microsoft через `microsoft-speech`

Модели транскрипции управляются на странице настроек Transcription. Текущие категории провайдеров транскрипции:

- OpenAI-совместимые через `openai-transcription`
- OpenRouter через `openrouter-transcription`
- ElevenLabs через `elevenlabs-transcription`
- Deepgram через `deepgram-transcription`
- Google через `google-transcription`

Это разделение важно, потому что у аудиомоделей есть зависящие от провайдера настройки голоса, формата, скорости, высоты тона, языка и распознавания, которые не применимы к моделям чата и эмбеддингов.

---

## Рекомендуемая ментальная модель

Для большинства Bot думайте о параллельных ролях моделей:

- **Чат-модель** — для обычных разговоров
- **Модель эмбеддингов** — для поиска по памяти
- **Модели речи / транскрипции / изображений** — для вспомогательных возможностей вроде синтеза речи, распознавания речи и генерации изображений

Не нужно заставлять одну модель делать всё.

# Встроенный провайдер памяти

Встроенный провайдер памяти — это стандартный бэкенд памяти, поставляемый с Memoh. Он работает с конвейером памяти Memoh и поддерживает:

- автоматическое извлечение воспоминаний из разговоров;
- семантический поиск воспоминаний во время чата;
- ручное создание и правку воспоминаний;
- процессы сжатия и перестроения памяти.

---

## Как это работает

Встроенный провайдер работает в режиме **graph**. Узлы и рёбра памяти хранятся в PostgreSQL как источник истины, а из них выводится Markdown-представление (bundle `memory/` плюс `MEMORY.md` в рабочем пространстве Bot), которое агент читает и редактирует.

Семантический поиск необязателен и надстраивается сверху:

| Слой | Хранилище | Требования | Что добавляет |
|-------|---------|--------------|--------------|
| **Graph** (всегда включён) | Узлы/рёбра памяти в PostgreSQL | Ничего сверх основной базы данных | Структурированное извлечение, связи между воспоминаниями, сжатие, перестроение |
| **Семантический индекс** (опционально) | База данных `pgvector` | База `[pgvector]` из Compose-стека **и** модель эмбеддингов, выбранная на провайдере | Поиск по векторной близости среди узлов памяти |

Если модель эмбеддингов не задана или база `pgvector` не настроена, провайдер всё равно работает в чисто графовом режиме; семантический поиск просто пропускается.

---

## Создание встроенного провайдера

1. Перейдите на страницу **Memory Providers**.
2. Нажмите **Add Memory Provider**.
3. Заполните поля:
   - **Name**: отображаемое имя этого провайдера.
   - **Provider Type**: выберите `builtin`.
4. Нажмите **Create**.

---

## Настройка встроенного провайдера

Создав провайдер, выберите его в списке и настройте параметры.

| Поле | Описание |
|-------|-------------|
| **Embedding Model** | Необязательно. Модель эмбеддингов от одного из ваших LLM-провайдеров. Когда она задана (и доступен `pgvector`), узлы памяти векторизуются и включается семантический поиск. Оставьте пустым для чисто графового режима. |

### Управление провайдерами

- **Edit**: выберите провайдер и обновите его настройки.
- **Delete**: удалите провайдер, которым больше не пользуетесь.

---

## Требования к инфраструктуре

### Только graph

Никакой дополнительной инфраструктуры сверх основной базы PostgreSQL.

### Семантический индекс

Стандартный стек Docker Compose уже включает сервис `pgvector` и соответствующую секцию в `config.toml`:

```toml
[pgvector]
enabled = true
host = "pgvector"
port = 5432
user = "memoh"
password = "memoh123"
database = "memoh_vector"
sslmode = "disable"
```

Затем выберите на провайдере **Embedding Model**. Эмбеддинги генерируются через выбранный LLM-провайдер (OpenAI, Gemini, Ollama, ...), поэтому у того провайдера должна быть модель с поддержкой эмбеддингов.

---

## Назначение провайдера памяти Bot

1. Перейдите на страницу **Bots** и откройте своего Bot.
2. Откройте вкладку **General**.
3. Найдите выпадающий список **Memory Provider**.
4. Выберите созданный провайдер.
5. Нажмите **Save**.

Если провайдер памяти не выбран, Bot не будет использовать эту конфигурацию провайдера в своих рабочих настройках.

---

## Работа с памятью после настройки

Как только провайдер памяти назначен Bot, самими воспоминаниями можно управлять на вкладке **Memory** этого Bot:

- создавать воспоминания вручную;
- извлекать воспоминания из разговоров;
- искать, править и удалять воспоминания;
- сжимать или перестраивать хранилище памяти.

О повседневных операциях с памятью читайте дальше в [Управлении памятью Bot](../../../guides/memory.md).

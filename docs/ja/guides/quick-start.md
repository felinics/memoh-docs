# クイックスタート

ゼロから始める完全チュートリアルです。アプリをインストールし、サインインして最初の Bot を作成し、実際の仕事を任せ、チャットプラットフォームから使えるようにします。所要時間は約 15 分です。

## 前提条件

- macOS、Windows または Linux のコンピューター。
- [Memoh Cloud](https://app.memoh.net) のアカウント。サインイン時にそのまま登録できます。

必要なのはこれだけです。Memoh Cloud にはホスト済みモデル（DeepSeek、Kimi、GPT、Claude など）が組み込まれているので、始めるのに API Key は一切要りません。

## ステップ 1：Memoh をインストールする

[ダウンロードページ](https://memoh.ai/desktop) からお使いのプラットフォーム向けのパッケージ（macOS は DMG、Windows はインストーラー、Linux は AppImage/deb/rpm）をダウンロードして開きます。

## ステップ 2：サインインする

接続画面で **Memoh Cloud** を選んでサインインします。アカウントがなければ、先に登録してください。

## ステップ 3：最初の Bot を作成する

**Bot → 新しい Bot** に進み、名前と表示名を入力して、**一般** タブで会話モデルを選びます。ホスト済みモデルはそのまま使えます。

次に Bot への指示を書きます。このステップが最も重要で、最もつまずきやすいところです。失敗の多くは、書き方が漠然としすぎていることにあります。1 つの仕事をはっきり伝えましょう。

> **名前：** Digest
>
> **役割：** 週次のリーディングダイジェスト
>
> **指示：** 私がこの 1 週間に送った記事を集めてください。毎週金曜日に、テーマごとにグループ化したダイジェストにまとめます。各記事は 1 文で要約して元のリンクを添え、最後に「もう一度読む価値あり」のセクションを付けてください。元のリンクは変更しないこと。いかなる内容も公開しないこと。

役割を 1 つに絞った Bot は、何でも屋の Bot よりはるかに多くの有効なコンテキストを蓄積できます。仕事が本当に別々の役割に分かれるときは、この Bot に積み増すのではなく、新しい Bot を作ってください。各 Bot は専用のワークスペース、メモリ、設定を持ちます。タブごとの説明は [Bot](./working-with-bots.md) を参照してください。

**チャット** をクリックして挨拶してみましょう。返事が来れば、モデルへの経路は通っています。

## 自分のモデルを使う（BYOK）

ホスト済みモデルとは別に、いつでも自分のモデルを持ち込めます（Bring Your Own Key）。

1. サイドバーで **プロバイダー** を開き、**プロバイダーを追加** をクリックします。
2. テンプレート（OpenAI、Anthropic、Gemini、DeepSeek、Zhipu、OpenRouter、Ollama など）を選んで API Key を入力します。OpenAI 互換エンドポイントの場合は、対応する Base URL も入力してください。
3. そのプロバイダーを開いてモデル一覧を**同期**するか、会話モデルを少なくとも 1 つ手動で追加し、Bot の **一般** タブでそのモデルに切り替えます。

BYOK のモデル使用量は、選んだプロバイダーの料金で課金されます。コーディングエージェントも同じ考え方です。Bot の **エージェント** タブで、自分のサブスクリプションまたは API Key を使って Claude Code や Codex にサインインしてください。プロバイダーごとのフィールドと注意点は [モデルプロバイダー](../integrations/providers/llm.md) にあります。

## ステップ 4：最初のタスクを任せる

良い最初の依頼は、次の 5 つの問いに答えています。

| 要素 | 答える問い |
|------|------------|
| **結果** | 終わったとき、何が存在しているべきか？ |
| **ソース** | どのファイル・サイト・会話が関係するか？ |
| **制約** | 何に触れてはいけないか、何にあなたの承認が要るか？ |
| **形式** | 結果はどんな形で届けるか？ |
| **確認ポイント** | いつ手を止めてあなたに確認すべきか？ |

外部へのログインなしに数分で結果を見たいなら、ドキュメントを 1 つアップロードして試してみてください。

```text
このドキュメントを 5 つの要点に要約してください。別のセクションに、文中のすべての日付・決定事項・
未解決の課題を列挙し、それぞれがどのページまたはどのセクションに由来するかを記してください。
元のファイルは変更しないでください。
```

Bot は自分のワークスペースの中でファイルを読み、結果を会話に書き戻します。Bot が生み出したものはすべてワークスペースに残り、[ファイル](./files.md) から閲覧・編集できます。

## ステップ 5：ワークスペースとブラウザを使わせる

ワークスペースは Bot が仕事をする場所です。Linux ファイルシステム、ターミナル、プリインストール済みのツールチェーン（Python、Node.js、uv、npm）を備えており、データクリーニングもスクリプトもビルドもそのまま実行できます。

```text
さっきアップロードした CSV から、email 列が空の行をすべて削除してください。
クリーニング後のファイルを渡して、何行削除したかを教えてください。
```

タスクに本物のブラウザが必要なとき（headless モードでは動かないサイトや、ログインしないと見られないページなど）は、Bot の **Desktop** タブで可視デスクトップを有効にします。起動すると Bot はヘッド付き Chrome を操作し、あなたはデスクトップパネルでその様子を見守れます。

ログインの壁にぶつかったら、自分で画面を引き継ぎましょう。パスワード、パスキー、またはワンタイムコードを入力してから、操作を Bot に返します。ブラウザセッションはそのワークスペースに保持されるため、以降のタスクでもログイン状態は続きます。

::: warning 権限は必要な分だけ
ワークスペースの権限は段階制です。チャットのみ、ファイルの読み取り、ファイルの書き込み、コマンドの実行、コンテナの管理。タスクに必要なレベルだけを与え、それ以上は与えないでください。[アクセス制御](./access.md) を参照してください。
:::

詳しくは [ワークスペース](./container.md) と [Browser / Computer Use](./browser-computer-use.md) を参照してください。

## ステップ 6：チャットプラットフォームから使う

Bot が最も役に立つのは、あなたが普段からチャットしている場所です。

1. Bot の **プラットフォーム** タブを開き、**追加** をクリックします。
2. プラットフォーム（Telegram、Slack、Discord、Feishu、DingTalk、WeCom、WeChat、QQ、LINE）を選び、そのプラットフォームの資格情報を入力します。
3. そのプラットフォームから Bot にメッセージを送ります。最初のメッセージでセッションが作成されます。`/help` を送ると、使える [スラッシュコマンド](./slash-commands.md) を確認できます。

これで、スマートフォンから仕事を任せて、同じ会話で結果を受け取れるようになります。プラットフォームごとの設定は [チャネル](../integrations/channels/index.md) を参照してください。

## ステップ 7：振り返って定着させる

何かが違ったら、そのまま伝えましょう。修正はその場かぎりの手直しではなく、長く効くルールとして言い換えます。

```text
今後のすべてのダイジェストはこの形式で：テーマごとにグループ化し、各記事 1 行、
リンクは行内に入れ、最後に「もう一度読む価値あり」のセクションを付ける。
```

一連の流れが安定したら、毎回入力し直すのはやめましょう。

- [スキル](./skills.md) として保存すれば、以後は一言で手順一式を呼び出せます。
- [スケジュールタスク](./schedule.md) にすれば、チャットなしで cron に従って自動実行されます。
- [長期メモリ](./memory.md) を使えば、好みやプロジェクトのコンテキストがその後のすべてのセッションに引き継がれます。

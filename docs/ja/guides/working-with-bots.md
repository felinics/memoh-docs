# Bot との協働

[クイックスタート](./quick-start.md) は Bot を動かすまでの話でした。このページは Bot をうまく使うための話です。どんなタスクを任せるか、依頼をどう伝えるか、ルールをどこに置くか、いつ 2 つの Bot に分けるか。後半は設定リファレンスとして、Bot の作成と詳細ページの各タブのフィールドを扱います。

## Bot に任せるのに向いたタスク

次の 3 つの条件をすべて満たすタスクは、Bot に任せるのに最適です。

- **結果が明確。** 終わったときに何が存在しているべきか（ファイル 1 つ、メッセージ 1 件、表 1 枚）を言葉にできる。
- **ソースに手が届く。** 関係するファイル・サイト・会話が、Bot が実際にアクセスできるものである。ワークスペースにアップロード済み、チャネルやサービスとして接続済み、あるいは公開されている内容。
- **成果物を確認しやすい。** 結果が正しいかどうか一目で分かれば、レビューのコストは低く済む。

3 つすべて満たしていても、まずは読み取り専用から始めましょう。読ませて整理させるところから入り、成果物を何度か確認してから、少しずつ権限を広げます。

## 依頼をはっきり伝える

良い依頼は 5 つの問い（結果・ソース・制約・形式・確認ポイント）に答えています。その表は [クイックスタート](./quick-start.md#ステップ-4-最初のタスクを任せる) にあります。ここでは実際の比較を 2 組見てみましょう。

::: warning 曖昧
> テックニュースを見ておいて、面白いものがあったら送って。
:::

ソースがなく（どのサイト？どのリポジトリ？）、届ける時刻もなく、「面白い」はあなたの代わりに下す主観的な判断のままです。これでは毎回のダイジェストが運まかせになります。

**こう直します。**

::: tip 具体的
> 毎営業日の朝 8 時に、私がフォローしているこれらのリポジトリの過去 24 時間の release と重要な issue をまとめて、1 通のダイジェストとして送ってください。各項目には出典を明記し、不確かな内容は推測せずに不確かだと言ってください。
:::

::: warning 曖昧
> このスプレッドシートをきれいにして。
:::

「きれいにする」が定義されていません。どの行が汚れたデータなのか、元のファイルに手を入れてよいのか、最後に何を返せばよいのか。Bot は手を付ける前に 3 回も推測しなければなりません。

**こう直します。**

::: tip 具体的
> さっきアップロードした CSV から、email 列が空の行をすべて削除してください。クリーニング後のファイルを渡して、何行削除したかを教えてください。元のファイルは変更しないでください。
:::

2 つの書き直しに共通するのは、ソースを名指しし、動作に枠をはめ、結果を一目で検証できるようにしていることです。

## 長期ルールの置き場所

指示には 2 種類あり、置き場所もそれぞれ違います。

- **長期ルール** は Bot 詳細ページの指示に書きます。役割、フォーマットの基準、常設の制約。以後のすべてのセッションで効きます。
- **1 回かぎりの依頼** はメッセージに書きます。今日のこのファイル、今週だけの例外。

ある修正を長く効かせたいなら、格上げしましょう。持続的なルールとして言い換えて指示へ移します。やり方は [クイックスタート](./quick-start.md#ステップ-7-振り返って定着させる) のステップ 7 のとおりです。手順一式が繰り返し登場するなら、[スキル](./skills.md) として保存すれば一言で呼び出せます。Bot に自分で覚えていてほしい好みは、[長期メモリ](./memory.md) に任せます。

## Bot を分けるタイミング

1 つの Bot に 1 つの仕事。役割を 1 つに絞った Bot が蓄積するコンテキストはその Bot を助け続けますが、何でも屋の Bot は自分の指示とメモリを薄めてしまいます。[クイックスタート](./quick-start.md) と [概要](./overview.md) でも述べたので、ここでは実用的な判断基準だけを足します。新しい要望の相手が違う、ソースが違う、または必要な権限が違うなら、2 つ目の Bot を作るべきです。

各 Bot は専用のワークスペース、メモリ、チャネル、権限境界を持ち、互いの中身は見えません。分けることで権限も正直に保てます。release の動向を読むだけの Bot に、コマンドを実行する権利は永遠に必要ないのです。

## 承認の習慣

タスクに必要なレベルだけを与えてください。ワークスペースの権限は、チャット、ファイルの読み取り、ファイルの書き込み、コマンドの実行、管理へと段階的に付与します。[アクセス制御](./access.md) を参照してください。

実際の運用では：

1. 新しいルーチンは読み取り専用で始め、書き込み・実行系のツール呼び出しは承認の後ろに残します。
2. 最初の数回の実行を確認してから、緩めることを検討します。
3. ワークスペースの外に出る動作（他人へのメッセージ送信など、外部への操作すべて）は、ルーチンに十分慣れた後も承認の後ろに残し続けます。

損得は単純です。リクエストを何度か承認する手間は、誤った書き込みを 1 回取り消す手間よりはるかに安く済みます。

## 作成

1. サイドバーから **Bot** に進みます。
2. **Create Bot** をクリックします。
3. 基本情報を入力します。
   - **Display Name**：外部に表示される名前
   - **Avatar**：アバター画像の URL
   - **Timezone**：空でも可。未設定ならユーザーまたはシステムのタイムゾーンを引き継ぎます
   - **ACL Preset**：`allow_all`（デフォルト許可）や `private_only`（プライベートチャットのみ）などのクイックポリシー
4. 作成します。

## 詳細ページ

カードをクリックして **詳細** に入ります。タブごとに受け持ちが分かれています。

| タブ | 内容 |
|-----|------|
| **概要** | ワークスペースランタイム、データベース、チャネル、メモリなどのヘルスチェック |
| **一般** | チャット/タイトル/画像生成モデル、メモリ/検索/TTS のバインド、タイムゾーン、言語、推論、Danger Zone |
| **Desktop** | ワークスペースのディスプレイランタイム、ヘッド付きブラウザ、進行中の display session |
| **Workspace** | コンテナ型ワークスペースの起動と停止、スナップショット、インポート／エクスポート |
| **ネットワーク** | ワークスペースのネットワークと overlay provider の状態／操作 |
| **メモリ** | メモリの閲覧・検索・作成・編集・圧縮 |
| **プラットフォーム** | 各メッセージチャネル（Telegram、Discord、Feishu など） |
| **アクセス** | ACL とデフォルトの許可／拒否 |
| **Toolの承認** | 人の確認が必要なツールの承認設定 |
| **エージェント** | チャットワークスペースで有効化できる ACP 互換コーディングエージェント（Codex、Claude Code など） |
| **コネクター** | Connect-It 経由で接続するサードパーティサービス（OAuth または API Key）。状態、有効化／無効化、再認証、切断 |
| **Hooks** | `/data/.memoh/hooks.json` に保存される Bot の自動化ルール |
| **MCP** | MCP 接続の管理（Stdio/Remote/OAuth） |
| **圧縮** | セッション圧縮の設定とログ |
| **スケジュール** | cron と実行ログ |
| **スキル** | スキルの Markdown ファイル |

ファイル、Terminal、デスクトップ／ブラウザの各パネルは、チャットのワークスペース領域でも使えます。会話を離れずにファイルを確認したり、シェルを実行したり、Bot のブラウザとデスクトップを見守ったりしたいときは、チャット内のワークスペースサイドバーを使ってください。

## まず設定すべきコア項目

1. Bot の **一般** タブを開き、まずモデルと各種バインドを設定します。
2. 定期的な自律タスクは **スケジュール** タブで管理します。
3. セッションが長くなってきたときの圧縮は **圧縮** タブで管理します。
4. ACL プリセットの後の微調整は **アクセス** タブで行います。

これらのリソースがまだなければ、先に作成しておきます。

- [モデルプロバイダーとモデル](../integrations/providers/llm.md)
- [組み込みメモリプロバイダー](../integrations/providers/memory/builtin.md)（使う場合）
- [ウェブ検索プロバイダー](../integrations/providers/web-search.md)
- [Agents / ACP](./acp.md)

## 一般タブのフィールド

| フィールド | 説明 |
|------|------|
| **Chat Model** | メインの会話モデル |
| **Title Model** | 任意。セッションタイトルの生成に使用 |
| **Image Generation Model** | 任意。`image-output` に対応したチャットモデルが必要 |
| **Memory Provider** | 長期メモリのバックエンド。組み込みタイプは専用のメモリ／埋め込みモデルも持てる |
| **Search Provider** | ウェブ検索にどのプロバイダーを使うか |
| **TTS Model** | TTS プロバイダーのフローから来るもので、通常のチャット用モデルプロバイダーからは選ばない |
| **Timezone** | 未設定ならユーザーのタイムゾーン、次いでシステムにフォールバック |
| **Language** | Bot が主に使う言語 |
| **Reasoning Effort** | 現在のチャットモデルが `reasoning` に対応している場合に利用可能。選べる値はモデルによる（例: `low` / `medium` / `high`） |

補足：

- **画像生成モデル** は意図的にメインのチャットモデルと分けてあります。「画像生成が得意な」モデルだけを個別に差し替えられるようにするためです。
- **TTS** は、**音声合成** 設定ページで設定した音声プロバイダーの `speech` モデルを使います。
- 選択したチャットモデルの `context_window` は、セッションステータスの表示と [セッションコンテキスト圧縮](./compaction.md) に影響します。

## 圧縮関連（ここでの対象は「セッション」）

ここで言うのは **現在のセッション** のコンテキストを短く圧縮する機能であって、メモリのエントリーを書き換えるものではありません。

| フィールド | 説明 |
|------|------|
| **Compaction Enabled** | セッション内で自動的に要約圧縮するかどうか |
| **Compaction Threshold** | 発動させる推定 token のしきい値 |
| **Compaction Ratio** | どの程度強く圧縮するか |
| **Compaction Model** | 任意。要約専用のモデル |

詳細は [セッションコンテキスト圧縮](./compaction.md) を参照してください。

## アクセスと ACL

作成時にはまず **ACL プリセット** を与え、その後 **アクセス** タブで微調整します。**プリセット** はデフォルトポリシーのひな形を与え、**Default Effect** は「どのルールにも一致しなかったとき」に許可するか拒否するかを決めます。

[セッション](./sessions.md) と Discuss のデフォルト挙動はそのページにあります。API や自動化で設定を管理する場合、設定には `discuss_probe_model_id` などの上級者向け項目もありますが、日常的な Bot 作成でまず触る必要はありません。

## ワークスペースのファイルとターミナル

ワークスペースのファイルとターミナルは、チャットのワークスペース UI から使います。前提として、その Bot に利用可能なワークスペースランタイムが必要です。ここでは次のことができます。

- ワークスペースのファイルを閲覧・編集する
- ワークスペース内でターミナルセッションを開く
- display を有効にしたうえでブラウザ／デスクトップ関連のツールを使う

ファイルの操作フローは [ファイル](./files.md) を、ヘッド付きブラウザとデスクトップ操作は [Browser / Computer Use](./browser-computer-use.md) を参照してください。

## 削除

**一般** タブ最下部の **Danger Zone** -> **Delete Bot** で、その Bot に関連するデータ（ワークスペースのファイルやメモリを含む）を削除します。**元に戻せません**。

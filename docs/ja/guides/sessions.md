# セッション

**セッション** は、ユーザーと Bot の間の独立した会話スレッドです。各スレッドは専用のコンテキストと履歴を持ち、話題やタスクを切り替えるときは新しいセッションを開くのが普通です。

---

## なぜ分離するのか

Bot と話した内容はすべて現在のセッションに積まれていきます。**新しいセッションを開く** とコンテキストが切り替わります。古い記録は残りますが、現在のスレッドの推論にはもう参加しません。

セッションは **Bot** 単位で分かれます。各 Bot がそれぞれ自分のセッション群を持ち、混ざることはありません。

---

## セッションタイプ

Memoh は 5 種類のセッションで異なる活動を区別します。

| タイプ | 説明 |
|------|------|
| **Chat** | 最も一般的な、ユーザーが始める会話。デフォルトはこれです。 |
| **Discuss** | 「観察」寄りのモード。Bot はデフォルトで黙っていてよく、モデルの出力は内心の独白として扱われます。送信系のアクションを使ったときだけ、チャネルに向けて本当に発言したことになります。 |
| **Schedule** | cron によってトリガーされます。 |
| **Subagent** | サブエージェントに委任されたときに作られます。 |
| **ACP Agent** | チャットワークスペースから、有効化済みの ACP 互換コーディングエージェントを使ったときに作られます。 |

通常の `/new chat`・`/new discuss` が直接作成するのは **Chat** と **Discuss** だけです。**ACP Agent** セッションは Agents/ACP ワークフローが作成・管理します。Schedule と Subagent は主にシステムが作成し、一覧では読み取り専用の記録のように見えます。

### Chat と Discuss の違い

**Chat**：

- 普通のアシスタントとのやり取りのように振る舞う
- ユーザーが 1 つ送れば、通常は目に見える返信が 1 つ返ってくることを期待する
- ウェブやダイレクトメッセージでは多くの場合これがデフォルト

**Discuss**：

- 多くはグループで登場し、Bot はみんなの会話を**見ている**
- 直接のテキスト出力はほとんどが内心の独白として扱われる
- チャネルに本当に発言するには、明示的な `send` などのアクションが必要
- **黙っていることも正常な選択肢**

Discuss があることで、Bot は一言ごとに返事をするカスタマーサポートではなく、「話に加わるかどうかは自分で決める」グループの一員らしく振る舞えます。

## `/new` で新しいセッションを開く

同じルート上で `/new` を使うと新しいセッションを開けます。古い履歴は削除されず、**現在の** コンテキストが切り替わるだけです。

- `/new`：現在の場面のデフォルトタイプで作成
- `/new chat`：通常の chat を強制
- `/new discuss`：discuss を強制

ACP Agent セッションは `/new` では作成されません。先に Bot 詳細の **エージェント** タブで ACP 互換エージェントを有効にし、チャットワークスペースから起動します。

**内蔵のウェブチャネル** のデフォルトは `chat`、**ダイレクトメッセージ** は多くが `chat`、**外部チャネルのグループチャット** は多くが `discuss` です。

**内蔵のウェブチャット** は `/new discuss` に対応していません。discuss を使いたい場合は、Telegram や Discord などの実際のチャネルを使ってください。

### 外部チャネルでは

Telegram、Discord、Feishu などの外部チャネルでは、`/new`・`/new chat`・`/new discuss` をメッセージとして Bot に送ります。すると Bot は、新しいセッションを作り、以降のメッセージをすべてそのスレッドに流し、古いセッションは保持したまま「現在」ではなくします。

特に役立つのはこんなときです。

- 話題を変えたくて、Bot に古いコンテキストを参照してほしくないとき。
- このスレッドが長くなりすぎて、きれいにやり直したいとき。
- 別々のタスクの間を行き来するとき。

### アプリでは

**アプリ** ではサイドバーの **New Session** のほか、セッションの切り替え、検索、タイプによる絞り込み（`chat`、`discuss`、`schedule`、`subagent`、`acp_agent`）、名前の変更、削除などができます。

## 管理

### 一覧

現在の Bot のセッションはサイドバーに並びます。各項目にはタイトル、タイプのアイコン、最終アクティブ時刻が表示されます。日常的に気にする **Chat / Discuss** は同じ一覧に混在します。どちらも「人が目にする種類のスレッド」だからです。

### 名前の変更

タイトルをクリックすると変更できます。トピックごとに整理するのに便利です。

### 削除

セッションを削除すると、そのスレッドの履歴は**完全に**消えます。

---

## ステータスパネル

ステータスパネルと `/status` が示すのは同じ情報です。このセッションのメッセージ数、**コンテキスト使用量**（`context_window` に対する割合）、**キャッシュヒット**、読み書き量、**このスレッドで使われたスキル** など。ここには **今すぐ圧縮** があり、トリガーされるのは [セッションコンテキスト圧縮](./compaction.md) であって、メモリのエントリーを書き換えるものではありません。

---

## 他の機能との関係

- **Discuss** は「グループで多く見て少なく話す」ためのものです。
- **Schedule** も時刻が来るとセッションを生成し、cron コマンドの実行結果を確認できます。
- **Subagent** はそれぞれ専用のセッションを持ち、委任されたタスクと対応します。サブエージェントは親 Bot のツール一式（ワークスペース、ブラウザ、メモリ、MCP）をほぼそのまま使えますが、ユーザーに直接メッセージを送ること、ユーザーに質問すること、さらにサブエージェントを重ねることはできません。委任の際、Bot はサブエージェントごとに別のチャットモデルを選ぶことも、現在の会話コンテキストを fork して渡すこともできます。セッション情報パネルで、現在アクティブなサブエージェントを確認できます。
- **ACP Agent** は、チャットワークスペースから起動したコーディングエージェントの作業を記録します。
- **長期メモリ** は Bot 全体で共有されます。どのスレッドから抽出されたものでも、他のスレッドからも検索できます（設定で許可している前提で）。

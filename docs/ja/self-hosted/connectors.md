# コネクター（Connect-It）

コネクターは、Bot に GitHub や Notion のようなサードパーティサービスのツールを使わせる仕組みです。裏側にあるのは [Connect-It](https://github.com/memohai/connect-it)——Memoh と一緒にデプロイされる併設サービスです。すべての資格情報（OAuth トークン、API Key）は Connect-It 側に保存され、Memoh が持つのはバインディング表だけです——どの Bot がどの接続に結び付いているか、ツール名前空間は何か、有効かどうか。

利用者から見ると、コネクターは単体でインストールするものではありません。[アプリ](../guides/supermarket.md)のコンポーネントとして App と一緒に届きます。App のマニフェストがどのコネクタータイプを使うか・必須かどうかを宣言しており、インストール後に Bot の **アプリ** タブで認証すれば完了です。このページの残りは運用者視点——Connect-It をどう動かすか、そして接続の裏側の仕組みです。

---

## サーバー側の前提

サーバーに Connect-It のエンドポイントが設定されて初めて、コネクター機能が現れます：

```toml
[connect_it]
base_url = ""   # 例 "http://connect-it:8421"
api_token = ""  # サーバー間の信頼トークン
```

両方を空にすると機能は無効になります。本番環境では対応する環境変数（`MEMOH_CONNECT_IT_BASE_URL`、`MEMOH_CONNECT_IT_API_TOKEN`）の使用を推奨します。

ワンライナーの Server Deploy は、新規インストール時に同居の Connect-It を自動で立ち上げます。詳しくは [Server Deploy](./docker.md#connect-it-コネクター) を参照してください。Connect-It が未設定の場合、コネクターに依存する App コンポーネントは「コネクターを利用できません」と表示されます。

---

## 認証と管理

コネクター付きの App をインストールすると、Bot の **アプリ** タブがコンポーネントとしてコネクターを一覧し、状態を表示します：**認証が必要**、**任意**、または **全ワークスペースで共有**。**認証する** をクリックしてバインディングを完了します——OAuth はポップアップで認可し（ブラウザにブロックされたら許可して再試行）、API Key 型なら資格情報フィールドに入力します。

各接続には状態が表示されます：

| 状態 | 意味 |
|------|------|
| **接続済み** | 正常。ツールは Bot から利用可能 |
| **認証待ち** | 接続はあるが OAuth が未完了。認証を済ませるか、切断する |
| **再認証が必要です** | 資格情報が期限切れか取り消し。**再認証** をクリック |
| **認証に失敗しました** | 前回の認証が失敗。**再認証** で再試行できる |
| **利用不可** | 設定中の Connect-It にこのコネクタータイプがない |
| **無効** | 停止中。ツールは Bot に渡されない |

接続は削除せずに**有効化／無効化**できます。**切断**はバインディングを Bot から外し、**さらに** Connect-It 側に保存された接続（資格情報を含む）も削除します——それを使っていた App は再認証が必要になります。

---

## ツールはどうやって Bot に届くか

会話の際、Memoh はその Bot の有効かつ正常な接続をすべて 1 つの MCP セッションに集約し、ツールソースとしてエージェントに渡します。コネクターのツールはワークスペースや MCP のツールと並んで現れます。

各接続はバインドの瞬間に、コネクタータイプから生成される**ツール名前空間**を受け取ります——GitHub 接続なら `github`、2 つ目は `github-2` です。名前空間はバインディングの生存期間中ずっと固定で、後から他の接続を増減しても、既存接続のツール名は変わりません。

# 使用场景

组合多种 Memoh 功能解决实际问题的即用型示例。每个场景独立成章：Bot 负责什么、用到哪些功能、怎么一步步搭起来。

好的 Bot 分工，是**负责一个可重复的结果**，而不是"大概管一类问题"。所有示例都从只读工作开始——先看它做得对不对，再逐步放权。

| 场景 | 它负责 |
|------|--------|
| [晨间简报](./morning-briefing.md) | 每个工作日开始前，把你关心的信息汇成一条消息 |
| [发版盯守](./release-watch.md) | 盯住一个你在等的外部变化，发生时第一时间找你 |
| [群聊值班助理](./group-duty-assistant.md) | 在团队群里答疑、发每日纪要 |
| [数据表格的日常维护](./data-upkeep.md) | 一份活的数据文件：建表、定期更新、异动先报告 |
| [带登录墙的网页任务](./gated-web-tasks.md) | 需要"看着屏幕"的网页操作：核对、表单、授权 |
| [云端写码与预览](./code-and-preview.md) | 在自己的工作区里写小项目，跑起来给你看 |
| [记得住事的个人助理](./personal-assistant.md) | 跨会话、跨平台记住你的偏好和项目进展 |

## 从示例到日常使用

1. **从只读开始。** 先让它"读并整理"，人工检查几次产出，再谈写入和执行。
2. **把约束写进指令。** 结果、来源、约束、形式、确认点——五件事说清楚（见[快速开始](../guides/quick-start.md)）。
3. **重复的流程存成[技能](../guides/skills.md)。** 一句话唤起整套动作，不用每次重打。
4. **稳定后再上[定时任务](../guides/schedule.md)。** 先用 Max Calls 试跑，确认无误再放开。
5. **写入和执行留在审批后面。** 即使流程已经很熟，对外动作也值得多看一眼。
6. **用[访问控制](../guides/access.md)限定谁能使唤它。** 尤其是接入群聊的 Bot。
7. **让[记忆](../guides/memory.md)沉淀偏好。** 纠正过的事不该再错第二次。

# 入门教程

Memoh 给你的机器人是真能干活的：每个机器人都有自己的工作区——完整的文件系统、可执行的终端、以及可选的带浏览器的可视化桌面——外加长期记忆和你本来就在用的聊天渠道。

本教程带你从空账号走到一个能完成真实工作的机器人，大约需要十五分钟。

<scalar-callout type="tip" title="想找安装方法？">
本页假定你已经能打开一个 Memoh 实例。如果你需要自己部署，请先看 [快速开始](./quick-start.md)。
</scalar-callout>

## 开始之前

你需要：

- 一个可访问的 Memoh 实例，以及能创建机器人的账号。
- 至少一个模型提供方的 API Key（OpenAI、Anthropic、Gemini、DeepSeek、智谱、OpenRouter、Ollama 等）。如果管理员已经配好了，跳过即可。

## 1. 登录

打开 Memoh Web UI 并登录。

如果这是一个全新实例，请立刻在 **Settings → Account** 修改初始密码。

界面语言、主题等选项随时可以在 [偏好设置](./preferences.md) 里调整，不影响下面的步骤。

## 2. 添加模型提供方

没有模型，机器人就无法思考。如果管理员已经配置过，跳过这一步。

1. 在侧边栏打开 **Providers**，点击 **Add Provider**。
2. 选择模板，填入 API Key，保存。
3. 打开该提供方并**同步**模型列表，或手动添加至少一个对话模型。

各家的客户端类型、Base URL 和注意事项见 [LLM 提供方](../integrations/providers/llm.md)。

## 3. 创建第一个机器人

进入 **Bots → New Bot**，填写名称和显示名，然后在 **General** 标签页选择对话模型。

接下来写它的指令。这一步最关键，也最容易出错——通常是写得太笼统。把一件事说清楚：

> **名称：** Digest
>
> **角色：** 每周阅读摘要
>
> **指令：** 收集我这一周发给你的文章。每周五整理成一份摘要，按主题分组：每篇一句话概括并附原始链接，最后加一节"值得再读"。原始链接保持不变。任何内容都不要公开发布。

职责单一的机器人能积累的有效上下文，远多于什么都干的机器人。当工作确实分成不同角色时，请新建一个机器人，而不是把这个越堆越重——每个机器人都有独立的工作区、记忆和配置。逐个标签页的说明见 [机器人](./bot.md)。

点击 **Chat** 打个招呼。收到回复就说明模型链路是通的。

## 4. 交给它第一个任务

一个好的首次请求会回答五个问题：

| 要素 | 它回答的问题 |
|------|------------|
| **结果** | 做完之后应该存在什么？ |
| **来源** | 涉及哪些文件、网站或对话？ |
| **约束** | 什么不能碰，什么需要你批准？ |
| **形式** | 结果以什么形式交付？ |
| **确认点** | 什么时候该停下来跟你确认？ |

想在几分钟内看到结果、又不需要任何外部登录，可以上传一份文档试试：

```text
把这份文档总结成五个要点。另起一节，列出其中所有的日期、决定和待解决问题，
并标注每条来自哪一页或哪一节。不要修改原文件。
```

机器人会在自己的工作区里读取文件，并把结果写回对话。它产出的一切都留在工作区，你可以在 [文件](./files.md) 里浏览和编辑。

## 5. 用起工作区和浏览器

工作区是机器人不再只是聊天机器人的地方。它有 Linux 文件系统、终端和预装工具链（Python、Node.js、uv、npm），能真正把活干完：

```text
把我刚上传的 CSV 里 email 列为空的行全部删掉。
给我清洗后的文件，并告诉我删了多少行。
```

当任务需要真实浏览器时——比如无头模式下会出错的站点，或需要登录才能访问的页面——在机器人的 **Desktop** 标签页启用可视化桌面。启动后，机器人会驱动一个有头 Chrome，你可以在 display 面板里看着它操作。

遇到登录墙时，你可以自己接管屏幕：输入密码、通行密钥或一次性验证码，然后把控制权交还给它。浏览器会话保留在该工作区中，后续任务依然是登录状态。

<scalar-callout type="warning" title="按需授权">
工作区权限是分级的：仅聊天、读文件、写文件、执行命令、管理容器。任务需要哪一级就给哪一级，不要多给。参见 [访问控制](./access.md)。
</scalar-callout>

详见 [工作区](./container.md) 与 [浏览器 / 电脑操作](./browser-computer-use.md)。

## 6. 接入聊天渠道

机器人在你本来就聊天的地方最有用。

1. 打开机器人的 **Platforms** 标签页，点击 **Add**。
2. 选择平台——Telegram、Slack、Discord、飞书、钉钉、企业微信、QQ、LINE、Matrix 或 Misskey——并填入该平台的凭据。
3. 从该平台给它发消息。第一条消息会创建会话；发送 `/help` 可以看到可用的 [斜杠命令](./slash-commands.md)。

从此你可以在手机上派活，然后在同一个对话里收结果。各平台的具体配置见 [渠道](../integrations/channels/index.md)。

## 7. 复盘，然后固化下来

有问题就直接说。把纠正写成长期规则，而不是一次性修补：

```text
以后所有的摘要都用这个格式：按主题分组，每篇一行，链接放在行内，
最后加一节"值得再读"。
```

当一套流程稳定下来后，就别再重复输入了：

- 存成 [技能](./skills.md)，以后一句话唤起整套流程。
- 变成 [定时任务](./schedule.md)，按 cron 自动运行，完全不需要聊天。
- 用 [长期记忆](./memory.md) 把你的偏好和项目上下文带进之后的每一次会话。

# 审批与信任

一个能写文件、能执行命令、能给人发消息的 Bot，需要一条你真正理解的边界。这一页从使用者的角度讲清这条边界：Bot 够得着什么、什么时候会停下来问、审批管得住什么又管不住什么。具体机制——成员列表、模式、规则——在 [访问控制](./access.md)。

## Bot 默认能碰什么

- **自己的工作区，仅此而已。** 每个 Bot 在自己隔离的容器工作区（`/data`）里干活。文件和状态都留在里面，Bot 之间互相看不见——见 [工作区](./container.md)。
- **只有你接入的渠道和授权的人。** Bot 能出现在某个平台，是因为你在 **平台** 标签页添加了它；能回应某个身份，是因为访问控制放行了。
- **每个人只有被授予的那一级。** 工作区权限分五级：聊天、读文件、写文件、执行命令、管理；任务需要哪级给哪级，不多给。级别定义见 [访问控制](./access.md)。

这些授权来自 Bot **Access** 标签页上的两份成员列表：**渠道成员** 管 IM 平台上的身份，**工作区成员** 管 Memoh 注册用户。

## 什么时候会来问你

写入和执行类工具调用可以要求人工批准，按 Bot 在 **Tool Approval** 标签页里配置。一个工具被设为需要确认时，流程是：

1. Bot 提出这个动作——具体到某一次工具调用，此时什么都还没执行。
2. 你批准或拒绝。
3. 只有批准的调用才会执行；被拒绝的永远不会跑。

审批永远发生在动作之前，所以审一眼请求就是控制权本身，而不是事后补救。等待中的请求也可能超时，不会无限等下去；错过了就让 Bot 把这个动作再试一次。

::: tip 想加更多关卡也可以
在 Tool Approval 设置之外，命中某个事件的 [Hook](./hooks.md) 也能主动发起人工审批——适合只看住某一类命令，而不是拦下整个工具。
:::

## 建议留在审批后面的动作

以下是建议，不是 Memoh 强制的默认值；当作一份稳妥的起步清单：

- **会离开工作区的消息**——发给其他人或公开发布的任何内容。
- **删除或覆盖文件**，尤其是不是 Bot 自己建的那些。
- **在工作区里执行安装和长时间运行的命令。**
- **任何花钱或触碰生产环境的动作。**

留在 Bot 自己工作区之内的动作（起草、整理、阅读）最先值得放出审批。这份建议怎么嵌进一个流程的生命周期，从第一次只读运行到逐步放宽，见 [和 Bot 协作](./working-with-bots.md)。

## 桌面接管与凭据

Bot 在可视化桌面里干活时撞上登录墙或验证码，就由你接管屏幕，亲手输入密码、通行密钥或一次性验证码，然后把控制权交还。凭据从你的键盘直接进网站——你从头到尾不需要把它告诉 Bot。

之后浏览器会话留在该工作区里，后续任务保持登录状态，不用再接管一次。见 [浏览器 / 电脑操作](./browser-computer-use.md) 与 [快速开始](./quick-start.md#第-5-步-让它用上工作区和浏览器)。

## 一条诚实的边界说明

::: warning 审批管不住的部分
审批拦的是「提议中的动作」——它不能撤销已经执行的工作，也收不回已经发出去的消息。拒绝一个请求只是拦下这一个请求，它不是回滚按钮。
:::

所以真正持久的习惯还是 [访问控制](./access.md) 里那条：按任务给最低级别，检查几次运行，再逐步放宽。对 Bot 的信任和对新同事的信任是同一种东西：靠证据一点点建立。

# 扩展能力怎么选

Memoh 有五种给 Bot 加能力的方式。单看名字很容易混，摆在一起就清楚了——所以直接摆在一起。

| 扩展方式 | 它是什么 | 放在哪 / 怎么触发 | 适合什么 |
|----------|----------|-------------------|----------|
| [技能](./skills.md) | 改变 Bot 做事方式的 `SKILL.md` 提示模块 | 在 Bot 工作区的 `/data/skills/` 下，从 **Skills** 标签页管理；在对话中唤起 | 那些本来每次都要重打一遍的流程和工作习惯 |
| [Hooks](./hooks.md) | 写在 `hooks.json` 里、可以运行命令或工具的事件规则 | 在 `/data/.memoh/hooks.json`，从 **Hooks** 标签页编辑；在 `PreToolUse`、`TurnEnd` 这类生命周期事件上触发 | 固定节点上的检查和附带动作，全程不经过聊天 |
| [MCP](./mcp.md) | 到外部 MCP 工具服务器的连接 | 按 Bot 在 **MCP** 标签页配置，Stdio 或 Remote 连接；发现的工具在对话中使用 | 接入一个本身就带 MCP server 的工具 |
| [连接器](./connectors.md) | 到 GitHub、Notion 这类服务的 OAuth 或 API Key 绑定 | 从应用市场的 **Connectors** 标签页连接，在 Bot 的 **Connectors** 标签页管理；服务的工具出现在对话里 | 让 Bot 用你在某个托管服务上的账号做事 |
| [应用市场](./supermarket.md) | Memoh 内置目录：一键安装打包好的应用——技能连同它的依赖和连接器 | 在 **设置** 下；装好的内容落进目标 Bot 自己的各个标签页 | 直接拿到现成能力，不用自己拼零件 |

不管能力从哪条路进来，最后都汇到同一个地方：连接器和 MCP 的工具在对话里与工作区工具并列出现，装好的技能出现在 Bot 的 **Skills** 标签页里，和手写的没有两样。

## 该用哪个？

- 想改 Bot 的做事方式 → [技能](./skills.md)。
- 想在某个事件点自动做事 → [Hooks](./hooks.md)。
- 想接一个有 MCP server 的工具 → [MCP](./mcp.md)。
- 想让 Bot 用你的 GitHub/Notion 账号 → [连接器](./connectors.md)。
- 想一键装现成的一套 → [应用市场](./supermarket.md)。

::: tip 它们可以叠着用
这五种不是互斥选项。应用市场装的一个应用可能同时带来技能和连接器，Hook 也可以看住经 MCP 接进来的工具。按上面的问题选，而不是每个 Bot 只挑一种。
:::

## 从哪开始

每种方式都有完整的一页，展开这张表压缩掉的细节：

- [技能](./skills.md)——`SKILL.md` 的写法、技能状态、收编发现的技能。
- [Hooks](./hooks.md)——事件目录、配置结构、怎么测试一条规则。
- [MCP](./mcp.md)——Stdio 与 Remote 连接、OAuth、工具发现。
- [连接器](./connectors.md)——连接状态、重新授权、工具命名空间。
- [应用市场](./supermarket.md)——浏览目录、安装到 Bot。

拿不定主意就先逛应用市场——装一个现成的包，先看看成品长什么样，再动手搭自己的。
